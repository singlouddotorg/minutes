Instructions and Workflow

Everything below covers the complete process, start to finish: recording a singing in Capture, then reviewing and preparing finished minutes in Compile.

Pre-Release

Minutes is still in testing. Any and all feedback is welcome — please use with caution, and keep a backup of anything important. Reach the developer, Kevin of SingLoud.org, at sacredharpbiblio@gmail.com.

Quick Start

  1. Open Minutes — one application, four stages, shown as numbered steps down the left.
  2. 1 Setup: find an existing singing (grouped by series, if it's a recurring one) or start a new one.
  3. 2 Capture: record the songs and officers live, during the singing.
  4. 3 Compile: after the singing, review what was logged and fill in anything that shouldn't burden someone logging live.
  5. 4 Export: preview and download the finished result.

The same singing carries across all four stages automatically — nothing needs to be downloaded and re-imported by hand between them. Each stage still has a working save/download of its own for backups.

Setup: Finding or Starting a Singing

  • Setup is the home screen. If your singing is part of a recurring series, previous occurrences appear grouped together — expand a series to see its dated occurrences, or use New Singing in This Series to start the next one, which carries the venue and Series Code forward but starts fresh on date, officers, and the song list. The same continuation is also available from inside any currently-open singing itself, as New Singing Based on This One — useful when you opened a singing directly (an individual file, say) rather than by browsing a series list.
  • A Series Code links occurrences of the same recurring singing together. Click Generate to get one — a short, readable, human-invented code becomes a real collision risk once many singings are compiled over the years, so the generated code is deliberately not a readable word. The field stays editable too, for the real case of matching a code someone else already started a series with; typing your own is just not the encouraged path for starting a new one.
  • Series grouping needs a Chromium-based browser (Chrome, Edge, Opera) to browse a local folder; Firefox and Safari don't support that yet. Click Open Singing, then Choose a Singing File to open a single file directly instead \u2014 that works everywhere, in every browser, regardless.
  • Once a singing is open, its name, date, and status stay visible at the top of the screen no matter which of the four stages you're in.

Preparing Before the Event

  • Minutes is built for a laptop, desktop computer, or a tablet with a physical keyboard — it isn't designed for phone-sized screens.
  • Open the app ahead of time, ideally before you arrive, so it's already loaded and ready. It's a single file with no install step, and works fully offline once open — nothing about logging songs depends on a network connection at all.
  • In Setup, either open a previous occurrence's next singing, or start a completely new one.
  • Fill in Event, Date, Location, and — if known — the Officers & Roles fields (Chair, Vice-Chair, Secretary, Treasurer, Arranger(s), Chaplain(s), Memorial Lesson Leader). None of these are required to start logging songs, but filling them in early means Compile won't need to guess later.
  • If it's useful, download an early backup CSV once the first few songs are in, just to confirm the whole save/export path works on this device before it matters.
Sacred Harp business-session officer elections are usually a ceremonial reconfirmation of whoever is already serving, not a new appointment. If that's the case, fill in Officers & Roles with the actual presiding officers at the very start of logging, rather than waiting for the business session to make it "official."

Recording (the Capture stage)

  • For each song: type the Leader, then the Page (e.g. 123, 45t, 45b for a top/bottom page), and press Enter — no button needed.
  • The song title looks itself up automatically from whichever songbook is selected. If a page could mean two different songs, this stage asks you to specify top or bottom rather than guessing. If a page doesn't exist in the book's index, it asks you to confirm before adding it, so a typo doesn't get logged as if it were real.
  • Multiple leaders on one song can be entered comma-separated in the Leader field.
  • Use Recess / Lunch / Announcements to mark breaks.
  • Tag a song Call Back (the leader who brings the class back together after a break), Memorial, or Special as it applies.
  • To correct a recent entry, tap it in the log to edit it in place — the same page/leader/duplicate checks apply to an edit as to a new entry.

Sessions, Days, and Locations

A singing in Minutes can span more than one session — a second day of a convention, a change of venue, or any other clearly distinct segment of the same overall event. This is different from starting a whole new singing:

  • Start New Singing begins an entirely new event and a new file. Use this when you're done with one singing and moving on to a completely different one — or return to Setup and open a different one.
  • Start New Session stays inside the same event and the same file. Use this for a new day, a changed location, or a distinct segment of the same convention.

Tapping Start New Session reopens the setup fields so you can update the Date and/or Location, add a session label if you like (e.g. "Day 2"), and update Officers & Roles if anything genuinely differs for this session — then confirm. Nothing already logged changes; everything from that point forward carries the new details.

A session can carry its own:

  • date
  • location
  • session label
  • officers, only where they actually differ from the event's usual officers

Saving and Backups

  • The Capture stage saves to this browser automatically as you go — no action needed. A status line shows Saved locally at [time], or a clear warning if local saving isn't working on this device.
  • If you accidentally refresh or close the tab, reopening on the same device and browser restores where you left off — the active singing, and which stage you were on.
  • Local saving alone isn't a substitute for a real backup — download or copy the CSV during the event as well, and definitely at the end.
  • An optional automatic periodic backup download exists (off by default) — turn it on if you'd like an extra copy saved to your Downloads folder every few minutes. It's a bonus, not a replacement for downloading the final file yourself.

Moving to Compile

  • The same singing carries into Compile automatically — visiting the Compile stage for the first time after recording picks up what was just logged, with no file to choose.
  • Compile checks the file's schema version. An unfamiliar-but-not-newer version is flagged clearly so you know to double-check the result, but the import still proceeds. A version genuinely newer than what this build understands is treated differently — that one's a real data-loss risk (re-exporting could silently drop whatever the newer schema added), so it blocks the import outright rather than just noting it, with a message pointing you to a version of Compile that actually supports it.
  • Event Details, Roles, and the Song List all auto-fill from what was recorded. The import message lists exactly what got filled in, so it's easy to spot-check.
  • Working from a file that didn't come through Setup — someone emailed you a CSV, say? Compile's own Import tab still takes a file directly, the same as it always has.

Reviewing and Correcting

Once in Compile, work through it before exporting:

  • Check Event Details and Roles for anything that auto-filled incorrectly or needs a human's judgment.
  • If the file has more than one session, a Sessions section appears on the Song List tab — one card per session, with its own location and any officer differences. Each officer there has three real choices: use the Event default, set none for that role this session, or name a different person for just that session. Two sessions sharing a date, location, or label are still tracked separately — Compile disambiguates the display automatically rather than merging them.
  • Fill in anything that shouldn't burden someone logging live: the full memorial lesson write-up, business-session details, secretary's report, and similar long-form content belong on the Names & Lists and Business tabs.
  • Resolve any row flagged for a missing name or page, an unrecognized tunebook code, or a likely duplicate leader spelling (the Song List tab clusters similar spellings and lets you merge them to one canonical form).
  • Where possible, clear flagged items before exporting a final version — a proofing pass now is easier than a correction after publication.

Terminology and Abbreviation Systems

Non-default tunebooks need a short code assigned once, on the Song List tab's Book Handling section. Minutes currently supports two independent code systems for this:

  • SingLoud.org Work Codes — used internally, and in every export except the dedicated SHMHA submission.
  • SHMHA abbreviations — used only in the SHMHA Minutes Book export, translated automatically from the Work Code you assign.

Neither system is more "correct" than the other — they're just the two published vocabularies the suite outputs today. Choosing the Type of output on the Export stage (Minutes Maker, SHMHA Minutes Book Submission, or Simple List) determines which applies, and the preview updates in real time, so you can check any of them before exporting.

Minutes Maker has its own per-song and summary-line checkboxes: show the song number, the title, both, or — if you uncheck both — Compile falls back to whichever one it actually has, rather than leaving a call-out with no identification at all. A song's source (tunebook) can also be shown on every call-out rather than only when it differs from the day's default book. None of this affects SHMHA Minutes Book Submission, which always applies its own fixed rule regardless of these checkboxes: printed-book songs are identified by page number only, and a title is used only when there's genuinely no page to give (an "Other" source).

How Tunebooks Are Recorded

Not every tunebook is known to this suite in the same depth. Books sit at one of four levels, and the levels are cumulative — each includes everything below it. A rough mnemonic: the level is how many things we know.

  • Level 0 — Other. We know nothing: just a name typed in passing while logging a singing. It appears in the CSV as the book value Other, and its songs are identified by title, since there's no page numbering to rely on.
  • Level 1 — Basic record. We know roughly one thing — the title, plus whatever scant details are on hand (compiler, year, codes). If a singing cites one of these, Capture and Compile will recognize the name and say so, but can't look up song titles by page.
  • Level 2 — Indexed. We know its pages: a complete page-by-page song index. This is the level that lets the Capture stage suggest a title the moment you type a page number, and lets Compile catch a page that doesn't exist in the book. Most books the suite ships with are here.
  • Level 3 — Enriched. A dedicated file exists per edition, holding — or building toward — the full scholarly record: attribution, concordances, editorial and publication history, bibliography. Level itself just means the file exists, not that it's finished; Tunebooks tracks completeness separately from level, showing a real core complete / core incomplete state (Common Name, Title Proper, and Compiler at minimum) alongside a short list of what else is still missing, rather than treating "has a file" as "done." A growing number of editions have a Tunebook File so far — see the Tunebook Library tab for the current count.

One file holds all of this: tunebook-library.js — every Work and Edition the system knows about, at whatever level each has been brought to. A Level 3 Edition also names its own dedicated Tunebook File (a separate JSON file per edition, in tunebook-files/), loadable on demand from Tunebooks' Library tab. Only Tunebooks edits any of this; Minutes reads tunebook data but never changes it. Tunebooks is a separate application with its own home, not a section of Minutes — it exists for the small number of people curating tunebook data, and nothing in Minutes depends on having it open.

Preview

The Export stage's preview represents the finished document as it stands right now. Any change you make — a correction on the Song List tab, a session's officer override, a different Type of output, a Minutes Maker checkbox, an opening-paragraph or prayer-phrasing choice — updates it immediately, so what you see is always current.

Exporting

The 4 Export stage currently exports these formats:

FormatTypical use
Plain textQuick copy into an email or document
MarkdownPosting to a website or wiki
HTMLReady to publish directly
PDF (print view)Opens your browser's print dialog — choose "Save as PDF"
Master CSVThe complete, authoritative project file — re-opens in any stage without losing anything already added
SHMHA Minutes BookMatches the Sacred Harp Musical Heritage Association's printed submission format exactly
Simple ListTerse, events-only list (officers, then each song's leader/page/source) for checking names and details, not publication

A Word (.docx) export previously existed but has been removed while its generator is rebuilt against the current data model — use plain text, Markdown, or HTML and paste into Word in the meantime.

Output profiles Partially implemented — the Export stage has a "Type of output" choice (Minutes Maker, SHMHA Minutes Book Submission, or Simple List) that determines which wording options apply and which export formats make sense, separately from which file format delivers it. The fuller original vision — additional named profiles beyond these three, such as Website, Archival Record, or Data Exchange, each with its own structural rules — is still just an idea.

MP3 Chapters and Video Markers Planned — a future version may use the order and timing already captured to generate chapter lists for a long recording, YouTube-style timestamp markers, or editing cue sheets. Not available yet.

There is one master project file for a singing, not a separate file per stage. Recording it creates the initial Master CSV; Compile enriching it — corrections, business notes, session overrides, and everything else on Compile's tabs — produces an updated Master CSV that supersedes the one before it. That newest Master CSV is the current authoritative record. The other formats in the table above (plain text, Markdown, HTML, PDF, the SHMHA submission) are one-way publication outputs generated *from* the Master CSV — they're not meant to be re-opened or resumed, and none of them replace it.

Troubleshooting

These entries mention "Capture" and "Compile" by name since those are the underlying tools that make up Minutes' Capture and Compile stages.

Capture won't re-load my own CSV

Capture's own re-import is strict: the column headers and schema version have to match exactly, since it's designed to resume an in-progress session precisely. A file edited in a spreadsheet program can sometimes reorder or rename columns; re-export from Capture if possible.

A file won't import into Compile, or imports with almost nothing recognized

Compile is much more tolerant than Capture — it matches columns by name, recognizes several older/alternate column names, and will still import a file with only some recognizable columns, flagging what it found. If a file truly imports with nothing usable, check that it has at least a Leader/Caller, Page, or Notes column under some name Compile recognizes.

"Old schema" or version-mismatch message

This behaves differently in each app, and Compile itself behaves differently depending on the specific mismatch. Capture blocks importing a file from a different schema version outright, since it's designed to resume a session exactly. Compile is more tolerant of an unfamiliar-but-older or otherwise-unrecognized version: it flags the mismatch and asks you to double-check the result more carefully than usual, but the import still proceeds. A file reporting a schema version genuinely newer than what the current build of Compile understands is the one case Compile also blocks outright, rather than just flagging — re-exporting an unfamiliar newer schema through this build's own current-schema header could silently discard whatever that newer schema added, which is a real data-loss risk, not just an unfamiliar label. Open a file like that in a version of Compile that actually supports its schema version instead.

Missing or unknown tunebook code

Assign the book a Work Code on the Song List tab's Book Handling section. If the SHMHA export shows a code you don't recognize, check the SHMHA Guide (in the Reference section of the left rail) for its abbreviation table.

Browser storage unavailable

The Capture stage will show a clear warning rather than silently failing to save. Download or copy your minutes right away if you see this, since local autosave isn't working on this device/browser combination.

Preview doesn't match what I expected

Check which Type of output is selected on the Export stage (Minutes Maker, SHMHA Minutes Book Submission, or Simple List) — they apply different style rules. Also check the Song List tab for a row that's still flagged (missing page, unresolved tag, or similar), since an unresolved row can print differently than a finished one.

DOCX export isn't available

Correct — it's been removed while it's rebuilt against the current data model. Use plain text, Markdown, or HTML and paste into Word in the meantime.

The instructional video won't load

It requires an internet connection once embedded. The written instructions on this page cover the same material and work offline.

Opening a singing in Setup doesn't seem to reach Minutes or Compile

It should — visiting either stage for the first time after opening or creating a singing hands that singing to the stage automatically, using the same real import logic a manual file load would. If a stage still looks empty after visiting it, that's worth reporting rather than assuming it's expected; it's not.

I opened Compile without a Capture CSV

That's fine — you can add songs by hand on the Song List tab. Importing a Capture file is the normal path, not a requirement.
